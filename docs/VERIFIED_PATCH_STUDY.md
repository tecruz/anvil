# Verified-patch study

Status: **milestones 1 and 2 implemented and verified offline**. No model has been called, no
approved run exists, and no effectiveness claim is made.

This study asks a different question from the earlier verification pilots:

> Does Anvil's local ticket-to-verification workflow help an agent produce a reviewable,
> verified patch on a real repository, compared with the same agent using plain OpenCode?

It deliberately tests the workflow as a bundle. It does not attribute a result to one
generated artifact, and it is separate from the hermetic benchmark and `eval-results/latest.json`.

`node --test scripts/test/verified-patch.test.ts` passes **9 tests, 0 failures**. The controls
cover: hidden acceptance failing on the base and passing with the reference fix; a correct
patch with an attested check of the final patch; the manifest-declared command being captured
and graded; hidden-acceptance failure despite a green visible check; a skipped check; a check
from the wrong directory; an edit after a green check; a broker fault; and the two arms

`node --test scripts/test/verified-patch-run.test.ts` passes **5 tests, 0 failures**. It checks
manifest loading, no-model preflight, a bounded preflight report, a deterministic run-spec hash,
and that `--run` refuses both without `ANVIL_EVAL=1` and without a matching approval file.

## Grading rule

A task counts as a success only when all three hold:

1. **In-scope patch.** At least one declared source/test path differs from the pinned base.
   Protected files (`verify.js`, `package.json`, `README.md`) are unchanged. Files generated by
   `anvil init` are excluded from the patch, so the assisted arm is not rewarded for them.
2. **Hidden acceptance.** A test the agent never saw is copied in after the run and passes on
   the final tree.
3. **Attested verification.** The repository check ran under harness control, from the declared
   directory, exited 0, and carries a fingerprint of the in-scope files **at execution time**
   equal to the final patch fingerprint. A green check followed by an edit is stale and fails.

A grader-side green run is not evidence about the agent's workflow. A written report is not
evidence of execution. Broker faults are run errors, not task failures.

## Arms

Both arms start from the same pinned fixture, model, tool access, task text and time limit, in
fresh directories with counterbalanced order.

- **Plain:** the fixture as checked in.
- **Anvil-assisted:** the fixture plus locally staged `anvil init` artifacts (`AGENTS.md`,
  `.agents/`, `.opencode/`, `.anvil/`). No network, no tracker credentials, no pushes.

## Declared-command capture

The broker now shims the manifest-declared command as well as the standalone script. For the
fixture, `npm run test` and `node verify.js` both map to the pre-snapshotted `verify.js`, and
both record the command the agent actually invoked. The grader accepts either form. A control
drives `npm run test` through the shim and requires a successful grade.

## What remains before any real run

1. Enroll public-repository tasks: a predeclared selection rule and pinned tasks whose
   acceptance test fails on the base and passes on a reference fix. The runner already
   preflights every manifest task without a model and records the result; the manifest
   currently contains only the local fixture.
2. A fresh predeclared design approved for its exact task list, model, seed, timeout, spend cap
   and scoring rule. The runner refuses `--run` unless `ANVIL_EVAL=1` and an approval file
   matches the SHA-256 of the run spec (manifest bytes, task cards, model, repetitions, timeout,
   seed, isolated config and Anvil commit). Power analysis for a large effect was 48 tasks /
   96 invocations at about 82%; that is a cost estimate, not a promise to detect a modest benefit.
3. One run only. No outcome-based retries, no added tasks, no pooling with earlier pilots.
   Claim a direction only if the predeclared threshold is met.

No model has been called. The maintainer's prior approvals covered earlier pilots, not this
study.
