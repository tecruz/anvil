# npm package-name check — 2026-11-17

This records the public and authenticated checks behind
[ADR-0023](../adr/0023-npm-package-name-is-anvil-workflows.md) and the Phase 4 name-control
criterion. Nothing was published, tagged, or released to a registry. No repository secret
value was read.

Environment: npm `11.6.2`, registry `https://registry.npmjs.org/`, run on 2026-11-17.

## Local authentication at the first check

```text
$ npm whoami
npm error code ENEEDAUTH
npm error need auth This command requires you to be logged in.

$ gh secret list --json name,updatedAt
[{"name":"OPENCODE_API_KEY",...},{"name":"OPENROUTER_API_KEY",...}]
```

At that point npm was unauthenticated, there was no user `.npmrc`, and no `NPM_TOKEN`
repository secret was listed. The public registry checks could not prove scope membership;
they could only show what was publicly visible. The maintainer later
authenticated, which is recorded under [Decision and confirmation](#decision-and-confirmation).

## The original scope was already in use

```text
$ npm view @anvil/cli --json
npm error code E404
npm error 404 Not Found - GET https://registry.npmjs.org/@anvil%2fcli - Not found
```

The 404 establishes that `@anvil/cli` was not publicly accessible at the time of the check,
not that it was never published. The scope was already in use:
`https://www.npmjs.com/org/anvil` listed the package names `@anvil/common-asc` and `common-asc`.
The scoped package was listed at 0.4.1, published 8 years ago, with `kyle-mccarthy` named as
that package's publisher.
The registry endpoint also listed the packages:

```text
GET https://registry.npmjs.org/-/org/anvil/package
200 {"common-asc":"write","@anvil/common-asc":"write"}
```

These results show an existing scope containing an unrelated package. The `"write"` values
are fields in that unauthenticated response, not evidence that this caller can publish.
The results do not establish who currently owns or administers the scope, or whether the
maintainer has access. A package publisher is not proof of scope ownership.
Maintainer control of `@anvil` was not established, so the maintainer chose a new scope.

## Decision and confirmation

The maintainer selected `@anvil-workflows/cli`, which was unclaimed at the time of this check.
The package was renamed accordingly, and the release workflow now refuses any other name.

The rename closed the **availability** question. The maintainer then created the
`anvil-workflows` npm org and authenticated on the build machine, which closes the **ownership**
question:

```text
$ npm whoami
tecruz

$ npm org ls anvil-workflows --json
{
  "tecruz": "owner"
}

$ npm org ls anvil-workflows
tecruz - owner

GET https://registry.npmjs.org/-/org/anvil-workflows/package
200 {}
```

The same registry endpoint returned `404 {"error":"Scope not found"}` before the org was
created and `200 {}` afterwards. Those public responses alone do not prove ownership;
the authenticated `npm org ls` result establishes that `tecruz`, the maintainer, has the
`owner` role in `anvil-workflows`.

`npm view @anvil-workflows/cli version` still returns 404, which is the intended state: name
control was confirmed without publishing anything.

After authentication, the repository secret-name listing was repeated on 2026-11-17. It
returned the same two names and no `NPM_TOKEN`; only names and timestamps were read:

```text
$ gh secret list --json name,updatedAt
[{"name":"OPENCODE_API_KEY","updatedAt":"2026-10-27T09:58:13Z"},{"name":"OPENROUTER_API_KEY","updatedAt":"2026-10-27T09:48:21Z"}]
```

Remaining, and deliberately not done here:

- no CI publishing credential was configured by this work, and no `NPM_TOKEN` repository
  secret was listed after authentication; this is separate from the local credential used
  by `npm login`;
- the registry channel stays unreleased until a first publication is separately approved;
- scope control must be re-checked immediately before the first release.
