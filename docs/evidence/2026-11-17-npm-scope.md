# npm package-name check — 2026-11-17

This records the public and authenticated checks behind
[ADR-0023](../adr/0023-npm-package-name-is-anvil-workflows.md) and the Phase 4 name-control
criterion. Nothing was published, tagged, or released to a registry. No repository secret
value was read.

Environment: npm `11.6.2`, registry `https://registry.npmjs.org/`, run on 2026-11-17.

## Local authentication at the first check

```text
$ npm whoami
npm error code ENEEDAUTH
npm error need auth This command requires you to be logged in.

$ gh secret list --json name,updatedAt
[{"name":"OPENCODE_API_KEY",...},{"name":"OPENROUTER_API_KEY",...}]
```

There was no user `.npmrc` and no `NPM_TOKEN` secret at that point, so this machine held no npm
credentials. A registry check from there could not prove scope membership; it could only show
what was publicly visible and whether a name was already taken. The maintainer later
authenticated, which is recorded under [Decision and confirmation](#decision-and-confirmation).

## The planned name is not available

```text
$ npm view @anvil/cli --json
npm error code E404
npm error 404 Not Found - GET https://registry.npmjs.org/@anvil%2fcli - Not found
```

`@anvil/cli` itself is unpublished. The scope, however, is not free. `https://www.npmjs.com/org/anvil`
lists two packages, including `@anvil/common-asc` (0.4.1, published 8 years ago), and names
`kyle-mccarthy` as the publisher. The registry org endpoint agrees:

```text
GET https://registry.npmjs.org/-/org/anvil/package
200 {"common-asc":"write","@anvil/common-asc":"write"}
```

A scoped package can only be published by a member of that org. The public record therefore
shows a collision with an unrelated owner; it does not show that the maintainer is a member,
and there is no local credential with which to check.

## Candidate scopes and names

```text
GET https://registry.npmjs.org/-/org/anvil-workflows/package
404 {"error":"Scope not found"}

GET https://registry.npmjs.org/-/org/anvilhq/package
404 {"error":"Scope not found"}

GET https://registry.npmjs.org/-/org/anvil-project/package
404 {"error":"Scope not found"}

GET https://registry.npmjs.org/-/org/anvil-dev/package
200 {}

GET https://registry.npmjs.org/-/org/getanvil/package
200 {}
```

- `@anvil-workflows`, `@anvilhq` and `@anvil-project` did not exist at the first check.
  `@anvil-workflows` was created later by the maintainer; the other two were not re-checked.
- `@anvil-dev` and `@getanvil` exist but are empty; they belong to someone else.
- `anvil-cli` is already published (0.1.2, "Anvil client for node").
- `@anvil-tools/cli` is already published (0.4.0).
- The npm scopes `@tecruz` and `@tiagotecruz` do not exist (`Scope not found`).

## Decision and confirmation

The maintainer selected `@anvil-workflows/cli`, which was unclaimed at the time of this check.
The package was renamed accordingly, and the release workflow now refuses any other name.

The rename closed the **availability** question. The maintainer then created the
`anvil-workflows` npm org and authenticated on the build machine, which closes the **ownership**
question:

```text
$ npm whoami
tecruz

$ npm org ls anvil-workflows --json
{
  "tecruz": "owner"
}

$ npm org ls anvil-workflows
tecruz - owner

$ GET https://registry.npmjs.org/-/org/anvil-workflows/package
200 {}
```

The same registry endpoint returned `404 {"error":"Scope not found"}` before the org was
created, so the transition from unclaimed to owned is observed, not assumed. `tecruz` is the
GitHub owner of this repository, and the owner role grants publish rights to the scope.

`npm view @anvil-workflows/cli version` still returns 404, which is the intended state: name
control was confirmed without publishing anything.

Remaining, and deliberately not done here:

- no npm token has been created;
- the registry channel stays unreleased until a first publication is separately approved;
- scope control must be re-checked immediately before the first release.
