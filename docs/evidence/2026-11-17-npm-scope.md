# npm package-name check — 2026-11-17

This records the public checks behind [ADR-0023](../adr/0023-npm-package-name-is-anvil-workflows.md)
and the Phase 4 name-control criterion. Nothing was published, tagged, or published to a
registry. No repository secret value was read.

Environment: npm `11.6.2`, registry `https://registry.npmjs.org/`, run on 2026-11-17.

## Local authentication

```text
$ npm whoami
npm error code ENEEDAUTH
npm error need auth This command requires you to be logged in.

$ gh secret list --json name,updatedAt
[{"name":"OPENCODE_API_KEY",...},{"name":"OPENROUTER_API_KEY",...}]
```

There is no user `.npmrc` and no `NPM_TOKEN` secret, so this machine holds no npm credentials.
A registry check from here cannot prove scope membership; it can only show what is publicly
visible and whether a name is already taken.

## The planned name is not available

```text
$ npm view @anvil/cli --json
npm error code E404
npm error 404 Not Found - GET https://registry.npmjs.org/@anvil%2fcli - Not found
```

`@anvil/cli` itself is unpublished. The scope, however, is not free. `https://www.npmjs.com/org/anvil`
lists two packages, including `@anvil/common-asc` (0.4.1, published 8 years ago), and names
`kyle-mccarthy` as the publisher. The registry org endpoint agrees:

```text
GET https://registry.npmjs.org/-/org/anvil/package
200 {"common-asc":"write","@anvil/common-asc":"write"}
```

A scoped package can only be published by a member of that org. The public record therefore
shows a collision with an unrelated owner; it does not show that the maintainer is a member,
and there is no local credential with which to check.

```text

404 {"error":"Scope not found"}

GET https://registry.npmjs.org/-/org/anvilhq/package
404 {"error":"Scope not found"}

404 {"error":"Scope not found"}

200 {}

GET https://registry.npmjs.org/-/org/getanvil/package

```

- `@anvil-workflows`, `@anvilhq` and `@anvil-project` did not exist when checked.
- `@anvil-dev` and `@getanvil` exist but are empty; they belong to someone else.
- `anvil-cli` is already published (0.1.2, "Anvil client for node").
- `@anvil-tools/cli` is already published (0.4.0).
- The npm scopes `@tecruz` and `@tiagotecruz` do not exist (`Scope not found`).

## Decision and remaining gap

The maintainer selected `@anvil-workflows/cli`, which was unclaimed at the time of this check.
The package was renamed accordingly, and the release workflow now refuses any other name.

This closes the **availability** question, not the **ownership** question. To satisfy the
Phase 4 criterion, the maintainer must create the `anvil-workflows` npm org from an
authenticated account and confirm publish access. Until then:

- no npm token has publish rights to the name;
- the registry channel stays unreleased;
- scope availability must be re-checked before the first release, because an unclaimed scope
  can be claimed by anyone.
